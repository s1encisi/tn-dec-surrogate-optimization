# 项目架构与设计取舍

## 原研究与公开演示

两者共享“目标定义、模型比较、关联解释、条件优化、证据核验”的逻辑，使用不同数据和配置。

| 范围 | 输入与计算 | 用途 |
|---|---|---|
| 原研究 | 受保护的厂级记录、完整候选库与冻结材料 | 中文论文和历史条件分析 |
| 公开演示 | 独立合成日记录、精简候选、三部分隔离和等预算搜索 | 验证软件流程与复现方法 |

公开演示不回退到私有路径，不读取原模型，也不复现论文实测精度。

## 演示实现

workflow.py负责生成、时间对齐、划分、模型比较和搜索。连续输入为t−1至t−3日均值，目标由公开的人工公式与噪声生成。

fit_select仅使用训练与验证部分选择模型。候选包括训练均值、二次特征Ridge、ExtraTrees和Huber堆叠。堆叠采用三折折外预测，各基础Pipeline在内折拟合插补与变换。候选固定后，在开发部分重拟合，再统一计算留出指标。

置换重要性使用开发阶段已选模型与验证数据，描述模型关联。原研究保留SHAP和ALE，演示没有将置换重要性标成SHAP。

build_cases在开发数据上拟合标准化与近邻，用局部边际分位区间和全局范围的交集确定PPA/DO经验矩形。该范围不是设备安全边界。

search_method为三个演化方法与随机参照分配相同预算。所有已评价候选用于提取非支配档案；运行后检查实际调用数和坐标范围。report.py根据已计算结果生成报告，不补写未经验证的性能结论。

## 关键取舍

- 分目标选择保留信息差异，不强求同一模型在两目标上胜出。
- 固定选择后再评价留出集，限制测试信息影响开发。
- 随机划分检验同分布估计，不能据此声称未来预测能力。
- 在共同尺度下搜索，再回到TN和DEC物理单位解释候选关系。
- 固定背景与支持范围，保证比较条件明确。
- 保留同预算随机参照及非一致排名，以质量和计算成本共同评价方法。
- 合成演示独立于原数据合同，不为演示方便绕过私有输入的哈希检查。

## 验证与落地位置

测试覆盖留出隔离、训练期预处理、数据划分、非支配计算、精确预算、候选边界、防覆盖和产物哈希。三个数据种子的重复运行用于检查流程稳定性。

当前可服务于离线评价、候选工况比较和现场验证设计。进入实际运行前，仍需确认监测语义、工程约束、跨期预测与反馈关系，并完成过程验证。公开仓库没有连接生产系统。
